# 实验五 Cache 实验完成步骤

## 1. 阅读实验要求

本实验需要完成三部分内容：

1. 修改原始矩阵乘法代码，使其能在 Windows 环境运行，并通过优化访存模式提升性能。
2. 编写访存测试程序，测量 x86 机器上的 Cache 层次结构、容量和 L1 Cache 行数。
3. 选做：尝试测量 TLB 的覆盖能力。

## 2. Windows 下修改原始代码

原代码使用 `sys/time.h`、`unistd.h` 和 `gettimeofday()`，这些接口主要用于 Linux/Unix。Windows 下需要改为高精度计时器：

- 删除 `#include <sys/time.h>` 和 `#include <unistd.h>`
- 增加 `#include <windows.h>`
- 使用 `QueryPerformanceFrequency()` 获取计时器频率
- 使用 `QueryPerformanceCounter()` 记录开始和结束时间
- 使用 `scanf()` 输入矩阵规模
- 程序结束前使用 `free()` 释放 `malloc()` 申请的内存

计时代码核心如下：

```c
LARGE_INTEGER frequency, start, end;
QueryPerformanceFrequency(&frequency);
QueryPerformanceCounter(&start);

/* 被测试代码 */

QueryPerformanceCounter(&end);
double seconds = (double)(end.QuadPart - start.QuadPart) / frequency.QuadPart;
printf("Execution time = %.6f seconds\n", seconds);
```

## 3. 矩阵乘法优化方法

原始矩阵乘法循环顺序为 `i-j-k`：

```c
for (i = 0; i < size; i++) {
    for (j = 0; j < size; j++) {
        c[i * size + j] = 0;
        for (k = 0; k < size; k++) {
            c[i * size + j] += a[i * size + k] * b[k * size + j];
        }
    }
}
```

问题在于：C 语言数组按行优先存储，`a[i*size+k]` 是连续访问，但 `b[k*size+j]` 是按列访问，步长为 `size * sizeof(float)`，矩阵较大时容易反复跨 Cache Line，Cache 命中率低。

优化后把循环顺序改为 `i-k-j`：

```c
for (i = 0; i < size; i++) {
    for (j = 0; j < size; j++) {
        c[i * size + j] = 0;
    }
}

for (i = 0; i < size; i++) {
    for (k = 0; k < size; k++) {
        float aik = a[i * size + k];
        for (j = 0; j < size; j++) {
            c[i * size + j] += aik * b[k * size + j];
        }
    }
}
```

这样 `b[k*size+j]` 和 `c[i*size+j]` 在最内层循环中都是连续访问，空间局部性更好。

## 5. Cache 容量测量方案

测量 Cache 容量时，核心思路是改变工作集大小并统计平均访存时间：

1. 申请不同大小的数组，例如 4KB、8KB、16KB，一直到 64MB。
2. 对每个数组重复访问大量次数。
3. 使用不同步长访问：
   - `1B`：顺序访问，容易被硬件预取优化。
   - `64B`：接近一个 Cache Line 的步长。
   - `4096B`：按页访问，更容易暴露 Cache/TLB 容量变化。
4. 计算每次访问的平均耗时。
5. 观察耗时明显上升的位置，即可估计 Cache 层级边界。

## 6. Cache 结果分析

本机处理器为 AMD Ryzen 7 7840H，系统报告：

```text
L1 Cache 总量：512KB
L2 Cache 总量：8192KB
L3 Cache 总量：16384KB
```

该 CPU 有 8 个核心，因此可以理解为：

```text
每核心 L1 约 64KB，其中 L1 Data Cache 约 32KB，L1 Instruction Cache 约 32KB
每核心 L2 约 1MB，8 核合计 8MB
共享 L3 Cache 约 16MB
```

实测数据在 512KB、8192KB、16384KB 附近能看到访问时间变化，与系统报告的 Cache 层级基本一致。

Cache Line 为 64B，因此：

```text
每核心 L1 Data Cache 行数 = 32KB / 64B = 512 行
每核心 L1 总行数 = 64KB / 64B = 1024 行
```

报告中按 L1 Data Cache 计算，写为 512 行。

## 7. TLB 选做测量

TLB 用于缓存虚拟地址到物理地址的转换结果。测量时可采用 4096B 步长，使每次访问尽量落到不同页：

```c
for (i = 0; i < iterations; i++) {
    index = (index + 4096) & mask;
    sum += array[index];
}
```

如果工作集页面数超过 TLB 能覆盖的范围，平均访问时间会上升。本次实验中，4096B 步长访问在 8192KB 到 16384KB 后上升明显，表示当访问页面数达到数千级别时，页表转换开销开始变大。

由于 TLB 测量容易受到操作系统调度、运行时环境、透明大页、硬件预取等因素影响，本实验只作为估算。若要得到更精确结果，应使用 C 或汇编编写随机页链指针追踪程序，并固定 CPU 亲和性。

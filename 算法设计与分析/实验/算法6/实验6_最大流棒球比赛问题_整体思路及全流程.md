# 实验6 最大流应用：棒球比赛淘汰问题整体思路及全流程

## 1. 实验目标

本实验研究“棒球比赛淘汰问题”：给定一个赛区内各球队当前胜场、负场、剩余比赛数，以及球队之间尚未进行的比赛安排，判断某支球队是否已经不可能以第一名或并列第一名结束赛季。

实验核心目标如下：

1. 掌握最大流算法的建模思想。
2. 将棒球比赛淘汰问题转化为最大流可行流问题。
3. 解释最大流为什么能够判断球队是否被淘汰。
4. 给出四支球队样例的求解结果。
5. 分别使用 Ford-Fulkerson、Edmonds-Karp 和 Dinic 三种最大流算法完成程序实现，并比较它们在相同数据上的结果与运行时间。

参考题目页面：https://coursera.cs.princeton.edu/algs4/assignments/baseball/specification.php

## 2. 问题抽象

设赛区共有 `n` 支球队。对第 `i` 支球队，已知：

- `w[i]`：当前胜场数；
- `l[i]`：当前负场数；
- `r[i]`：剩余比赛数；
- `g[i][j]`：球队 `i` 和球队 `j` 之间尚未进行的比赛数。

若判断目标球队为 `x`，则它的理论最高胜场为：

```text
Wmax = w[x] + r[x]
```

若存在某支球队 `i` 满足：

```text
w[i] > Wmax
```

则 `x` 显然已经被淘汰，因为即使 `x` 剩余比赛全胜，也无法追上 `i`。这称为平凡淘汰。

如果不存在平凡淘汰，还需要判断剩余赛程是否能够安排出一种结果，使得所有其他球队的最终胜场都不超过 `Wmax`。这一部分需要使用最大流。

## 3. 流网络构造原理

对目标球队 `x`，构造一个流网络。网络只考虑不包含 `x` 的其他球队之间的剩余比赛，因为我们在判断 `x` 是否还有可能夺冠时，可以假设 `x` 自己剩余比赛全部获胜。

![以 Philadelphia 为目标球队的流网络示意](figures/flow_network_philadelphia.svg)

网络包含四类节点：

1. 源点 `s`；
2. 比赛节点：每个不包含 `x` 的剩余比赛组合 `(i, j)` 对应一个节点；
3. 球队节点：除 `x` 外，每支球队对应一个节点；
4. 汇点 `t`。

边和容量设置如下：

1. `s -> 比赛节点(i, j)`，容量为 `g[i][j]`。
   这表示球队 `i` 和 `j` 之间还有多少场比赛必须分配胜者。

2. `比赛节点(i, j) -> 球队节点i` 和 `比赛节点(i, j) -> 球队节点j`，容量设为无穷大。
   这表示这几场比赛的胜场可以分配给 `i`，也可以分配给 `j`。

3. `球队节点i -> t`，容量为 `Wmax - w[i]`。
   这表示球队 `i` 最多还能赢多少场，才能保证最终胜场不超过目标球队 `x` 的理论最高胜场。

如果所有从源点出发的边都能被最大流完全填满，说明所有剩余比赛都可以被合理分配胜者，并且没有任何球队最终胜场超过 `x` 的最高胜场。因此 `x` 没有被淘汰。

反之，如果源点边不能全部满流，说明无论如何安排比赛结果，都会有某些球队的胜场超过 `x`，因此 `x` 已经被淘汰。

## 4. 为什么最大流能解决该问题

### 4.1 可行赛程到可行流

假设存在一种剩余赛程结果，使目标球队 `x` 能够并列第一或第一。

对于任意一场不含 `x` 的比赛，如果胜者是球队 `i`，则把 1 单位流量从对应比赛节点流向球队节点 `i`。若 `i` 和 `j` 之间有多场比赛，则按照这些比赛的胜负结果分配对应数量的流量。

由于每场比赛必然产生一个胜者，所以从源点到每个比赛节点的容量都可以被用满。又因为这种赛程保证所有球队最终胜场不超过 `Wmax`，所以球队节点到汇点的容量也不会被突破。因此，该赛程对应一个满流方案。

### 4.2 可行流到可行赛程

反过来，若最大流能使所有源点边满流，则每个比赛节点收到的流量都等于该组球队之间的剩余比赛数。

比赛节点流向两个球队节点的流量可以解释为这些比赛分别由哪支球队获胜。球队节点到汇点的容量限制保证每支球队新增胜场不超过 `Wmax - w[i]`，即最终胜场不超过目标球队 `x` 的理论最高胜场。

因此，满流方案可以还原为一种合法的赛程结果，使 `x` 仍然有机会获得第一或并列第一。

### 4.3 关键定理

目标球队 `x` 未被淘汰，当且仅当上述流网络中所有从源点 `s` 指向比赛节点的边都满流。

这个定理的作用是把“所有可能比赛结果的组合搜索”转化为一次最大流计算。原问题若直接枚举，每场比赛都有不同胜者选择，组合数会指数增长；最大流建模后，只需判断一个网络是否存在满足容量约束的可行流。

## 5. 淘汰证书

如果球队被淘汰，除了输出“被淘汰”，还需要给出一个淘汰证书 `R`，即一组共同导致目标球队不可能夺冠的球队。

实现中：

- 平凡淘汰时，证书可以直接取胜场已经超过 `Wmax` 的球队；
- 非平凡淘汰时，在最大流结束后的残量网络中，从源点仍可到达的球队节点构成集合 `R`。

这个集合来自最小割。它给出了导致无法满流的瓶颈，也就是目标球队被淘汰的原因。

## 6. 算法实现思路

本实验实现文件为：

```text
BaseballElimination.java
```

![棒球比赛淘汰问题算法流程](figures/algorithm_flow.svg)

实现结构如下：

1. 读取输入文件
   - 第一行读取球队数量 `n`；
   - 每支球队读取名称、胜场、负场、剩余比赛数和对阵矩阵；
   - 使用 `Map<String, Integer>` 建立球队名称到编号的映射。

2. 判断平凡淘汰
   - 对目标球队 `x` 计算 `Wmax = w[x] + r[x]`；
   - 若存在其他球队当前胜场超过 `Wmax`，直接返回淘汰证书。

3. 构造最大流网络
   - 为每个不含 `x` 的球队对 `(i, j)` 建立比赛节点；
   - 为每支非目标球队建立球队节点；
   - 加入源点、汇点和三类容量边。

4. 执行最大流
   - Ford-Fulkerson：使用 DFS 寻找任意增广路；
   - Edmonds-Karp：使用 BFS 寻找最短增广路；
   - Dinic：先用 BFS 构造分层图，再用 DFS 在分层图上寻找阻塞流；
   - 三种算法都在残量网络中不断增广，直到源点到汇点不存在增广路。

![Dinic 最大流执行过程](figures/dinic_process.svg)

本实验程序把流网络构造逻辑与最大流求解逻辑分开。也就是说，三种算法面对的是完全相同的棒球淘汰流网络，区别只在“如何求最大流”。这样可以保证比较结果公平，并且便于观察不同最大流算法的效率差异。

5. 判断是否淘汰
   - 统计所有 `s -> 比赛节点` 的总容量；
   - 若最大流值等于该总容量，则目标球队未被淘汰；
   - 否则目标球队被淘汰。

6. 输出证书
   - 在残量网络中从源点做 BFS；
   - 所有仍可到达的球队节点对应的球队组成淘汰证书。

## 7. 代码与算法思想的对应关系

程序中的核心方法 `certificateOfElimination(team)` 对应实验算法主流程。

- 它首先计算目标球队的理论最高胜场，完成平凡淘汰判断。
- 若平凡淘汰不成立，则调用网络构造逻辑。
- 网络中的比赛节点对应“剩余比赛必须产生胜者”这一约束。
- 球队节点到汇点的容量对应“其他球队不能超过目标球队最高胜场”这一约束。
- Ford-Fulkerson、Edmonds-Karp 或 Dinic 最大流的返回值都对应“能否安排完所有剩余比赛”。
- 残量网络可达点对应最小割来源侧，用来生成淘汰证书。

因此，代码不是单纯调用最大流，而是把每一类棒球比赛约束都转换成了流网络中的容量限制。

### 7.1 Ford-Fulkerson 算法原理

Ford-Fulkerson 是最大流问题中最基础的增广路算法。它的核心思想是：只要在残量网络中还能找到一条从源点 `s` 到汇点 `t` 的可行路径，就沿着这条路径增加流量。

具体步骤如下：

1. 初始时，所有边上的流量都为 0。
2. 在残量网络中寻找一条从 `s` 到 `t` 的增广路。
3. 计算这条路径上的最小剩余容量，记为瓶颈容量。
4. 将瓶颈容量沿路径加入正向边，并在反向边中加入对应残量。
5. 重复上述过程，直到残量网络中不存在从 `s` 到 `t` 的路径。

本实验中的 Ford-Fulkerson 使用 DFS 寻找增广路。它的优点是思想简单，能清楚体现“不断改进当前流”的过程；缺点是每次找到的增广路不一定好，算法效率会受路径选择影响。

### 7.2 Edmonds-Karp 算法原理

Edmonds-Karp 是 Ford-Fulkerson 的一种改进。它仍然使用“寻找增广路并增广”的思想，但规定每次都用 BFS 在残量网络中寻找边数最少的增广路。

具体步骤如下：

1. 初始流量为 0。
2. 在残量网络中用 BFS 寻找从 `s` 到 `t` 的最短增广路。
3. 计算该路径上的瓶颈容量。
4. 沿该路径增广，并更新正向边和反向边的残量。
5. 重复 BFS，直到找不到增广路。

由于 BFS 总是选择最短增广路，Edmonds-Karp 避免了 Ford-Fulkerson 中路径选择过于随意的问题，因此具有稳定的多项式时间复杂度。它适合作为最大流算法比较中的标准对照算法。

### 7.3 Dinic 算法原理

Dinic 算法进一步提高了求最大流的效率。它不是每次只寻找一条增广路，而是先用 BFS 构造分层图，再在分层图中通过 DFS 尽可能多地寻找增广流，直到当前分层图中无法继续增广为止。

具体步骤如下：

1. 在残量网络中用 BFS 从源点出发，给每个可达点标记层数。
2. 只保留从第 `k` 层指向第 `k + 1` 层的有效边，形成分层图。
3. 在分层图中用 DFS 多次寻找增广路，并不断推送流量。
4. 当分层图中无法继续从源点向汇点推送流量时，得到一个阻塞流。
5. 重新构造新的分层图，重复上述过程。
6. 如果 BFS 已经无法到达汇点，则最大流计算结束。

Dinic 的优势在于一次 BFS 后可以完成多次增广，减少了重复搜索的开销。在本实验的棒球淘汰网络中，Dinic 通常比 Ford-Fulkerson 和 Edmonds-Karp 更快。

## 8. 四支球队样例结果

输入文件：`data/teams4.txt`

样例数据对应 Atlanta、Philadelphia、New_York、Montreal 四支球队。

四支球队的求解结果如下：

| 球队 | 最高可能胜场 | 是否被淘汰 | 淘汰证书 R | 说明 |
|---|---:|---|---|---|
| Atlanta | 91 | 否 | 无 | 存在一种剩余赛程安排，使其他球队最终胜场不超过 Atlanta |
| Philadelphia | 83 | 是 | `{ Atlanta, New_York }` | 非平凡淘汰，需要通过最大流和最小割得到证书 |
| New_York | 86 | 否 | 无 | 存在合法赛程使 New_York 仍可并列第一或第一 |
| Montreal | 80 | 是 | `{ Atlanta }` | 平凡淘汰，因为 Atlanta 当前已有 83 胜，超过 Montreal 的最高可能胜场 |

三种最大流算法在该样例上的结果完全一致：

| 算法 | Atlanta | Philadelphia | New_York | Montreal |
|---|---|---|---|---|
| Ford-Fulkerson | 未淘汰 | 被 `{ Atlanta, New_York }` 淘汰 | 未淘汰 | 被 `{ Atlanta }` 淘汰 |
| Edmonds-Karp | 未淘汰 | 被 `{ Atlanta, New_York }` 淘汰 | 未淘汰 | 被 `{ Atlanta }` 淘汰 |
| Dinic | 未淘汰 | 被 `{ Atlanta, New_York }` 淘汰 | 未淘汰 | 被 `{ Atlanta }` 淘汰 |

对应的程序输出为：

```text
Atlanta is not eliminated
Philadelphia is eliminated by the subset R = { Atlanta New_York }
New_York is not eliminated
Montreal is eliminated by the subset R = { Atlanta }
```

解释：

- Atlanta 未被淘汰；
- Philadelphia 虽然理论最高能达到 83 胜，但 Atlanta 和 New_York 之间仍有比赛，相关赛程约束使它无法并列第一；
- New_York 未被淘汰；
- Montreal 最高只能达到 80 胜，而 Atlanta 已经有 83 胜，因此被平凡淘汰。

```text
305 / 4 = 76.25
```

## 10. 复杂度分析

对某个目标球队 `x`，除去 `x` 后还有 `n - 1` 支球队。

比赛节点数为：

```text
C(n - 1, 2) = (n - 1)(n - 2) / 2
```

球队节点数为：

```text
n - 1
```

加上源点和汇点，网络顶点数为：

```text
V = C(n - 1, 2) + (n - 1) + 2 = O(n^2)
```

边数包括：

- 源点到比赛节点的边：`C(n - 1, 2)`；
- 每个比赛节点到两个球队节点的边：`2C(n - 1, 2)`；
- 球队节点到汇点的边：`n - 1`。

所以边数为：

```text
E = 3C(n - 1, 2) + (n - 1) = O(n^2)
```

本实验比较三种最大流算法：

| 算法 | 增广路选择方式 | 时间复杂度 | 代入本实验网络规模后的复杂度 | 实验作用 |
|---|---|---|---|---|
| Ford-Fulkerson | DFS 寻找任意增广路 | `O(EF)` | `O(n^2F)` | 展示最大流最基本思想 |
| Edmonds-Karp | BFS 寻找最短增广路 | `O(VE^2)` | `O(n^6)` | 作为 Ford-Fulkerson 的稳定改进版本 |
| Dinic | BFS 分层图 + DFS 阻塞流 | 一般网络为 `O(V^2E)` | `O(n^6)` | 作为本实验的高效主算法 |

其中 `F` 表示最大流值，也就是所有需要分配的剩余比赛总数。对本实验来说：

```text
F = sum(g[i][j]), i != x, j != x, i < j
```

### 10.1 Ford-Fulkerson 复杂度

Ford-Fulkerson 每次用 DFS 找到一条增广路。一次 DFS 最多扫描所有边，因此单次寻找增广路的时间为：

```text
O(E)
```

如果所有容量都是整数，每次增广至少会让总流量增加 1。设最大流值为 `F`，则最多增广 `F` 次，所以总时间复杂度为：

```text
O(EF)
```

在本实验中，`E = O(n^2)`，因此 Ford-Fulkerson 的复杂度可以写成：

```text
O(n^2F)
```

这个复杂度与最大流值 `F` 有关。如果剩余比赛总数较大，Ford-Fulkerson 的运行次数可能明显增加。

### 10.2 Edmonds-Karp 复杂度

Edmonds-Karp 每次用 BFS 寻找最短增广路。一次 BFS 的时间复杂度为：

```text
O(E)
```

该算法的关键性质是：每条边成为关键瓶颈边的次数有限，整体增广次数最多为 `O(VE)`。因此总时间复杂度为：

```text
O(VE^2)
```

在本实验中，`V = O(n^2)`，`E = O(n^2)`，代入可得：

```text
O(VE^2) = O(n^2 * (n^2)^2) = O(n^6)
```

相比 Ford-Fulkerson，Edmonds-Karp 的优点是复杂度不再依赖最大流值 `F`，因此理论上更稳定。

### 10.3 Dinic 复杂度

Dinic 每一轮先用 BFS 构造分层图，再在分层图中用 DFS 寻找阻塞流。

构造分层图需要扫描边，时间为：

```text
O(E)
```

在一轮分层图中寻找阻塞流时，每条边在当前层次结构中被推进或跳过的次数有限，因此一轮阻塞流计算通常记为：

```text
O(VE)
```

一般网络中，Dinic 最多进行 `O(V)` 轮分层图构造，所以总时间复杂度为：

```text
O(V^2E)
```

在本实验中，`V = O(n^2)`，`E = O(n^2)`，代入可得：

```text
O(V^2E) = O((n^2)^2 * n^2) = O(n^6)
```

虽然 Edmonds-Karp 和 Dinic 代入后都可写成 `O(n^6)`，但 Dinic 每轮可以在分层图中推送多条增广流，实际运行中通常更快。本实验 `teams12.txt` 的测试结果也体现了这一点。

由于本实验的流网络规模为 `V = O(n^2)`、`E = O(n^2)`，三种算法都可以完成测试数据。但随着球队数和剩余比赛数增大，Dinic 通常比前两种算法更适合作为实际求解方法。

## 12. 实验总结

本实验的关键在于识别棒球比赛淘汰问题中的两个约束：

1. 每一场剩余比赛必须产生一个胜者；
2. 若目标球队仍有夺冠可能，则其他球队的最终胜场不能超过目标球队的理论最高胜场。

最大流网络恰好能够同时表达这两个约束。源点到比赛节点的容量保证所有剩余比赛都被安排；比赛节点到球队节点的流向表示胜场分配；球队节点到汇点的容量限制其他球队最多还能赢多少场。

当最大流能够填满所有源点边时，说明存在一种合法赛程使目标球队不被淘汰；否则，目标球队已经被数学淘汰。最小割进一步给出淘汰证书，使算法不仅能判断结果，还能解释原因。
